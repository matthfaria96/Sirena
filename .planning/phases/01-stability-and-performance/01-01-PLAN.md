Add `import os` at the top. Add `private static let log = Logger(subsystem: "Sirena", category: "ClipboardStorage")` (os.Logger, not swift-log; do not use print).

Replace `init()` body with a three-step recovery:
1. `do { container = try ModelContainer(for: HistoryItem.self, configurations: ModelConfiguration(url: url)); return } catch { Self.log.error("Clipboard store failed to open: \(error.localizedDescription, privacy: .public)") }`
2. Call `Self.moveStoreAside(url)` then retry the same `ModelContainer(for:configurations:)` once in a `do/catch`; on success `return`.
3. Final fallback: `container = Self.inMemoryContainer()`.

Add `private static func moveStoreAside(_ url: URL)`: build a suffix `".corrupt-\(Int(Date().timeIntervalSince1970))"`; for each of the three paths `url.path`, `url.path + "-wal"`, `url.path + "-shm"`, if the file exists, `try? FileManager.default.moveItem(atPath: path, toPath: path + suffix)`. If moving the main file fails, `try? FileManager.default.removeItem(atPath:)` it so the retry can create a fresh store. Log each move at `.notice`.

Add `private static func inMemoryContainer() -> ModelContainer`: `do { return try ModelContainer(for: HistoryItem.self, configurations: ModelConfiguration(isStoredInMemoryOnly: true)) } catch { fatalError("In-memory clipboard store unavailable: \(error)") }`. This is the only remaining fatalError; an in-memory SwiftData store failing means the model itself is broken (a programmer error), not a user-data problem. Leave a one-line comment saying so.

Because `container` is a stored `var` and `init` returns early, make sure every path assigns `container` before returning (Swift will enforce this). Do not touch any other method in the file.
